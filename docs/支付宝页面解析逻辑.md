# 支付宝页面解析逻辑

> AlipayScreenExtractor 完整解析策略文档  
> 最后更新: 2026-06-14 | 适配至: 碰一碰支付

---

## 一、解析流程总览

```
parse(rootNode)
  ├─ DFS 收集全量 text + contentDescription → texts 列表
  ├─ Step 1: 门禁校验 — 文本内容匹配（不依赖 ¥ 符号）
  │   ├─ texts.size >= 4
  │   ├─ texts.first() 以 "支付成功" 或 "转账成功" 开头
  │   └─ "完成" ∈ texts
  ├─ Step 2: 实付金额提取 — 嵌入格式 (Format A) → 拆分格式 (Format B) fallback
  └─ Step 3: 按类型分流
      ├─ 支付成功 → ¥ pair 自适应 Body 定位 → extractPayment()
      └─ 转账成功 → 纯文本 Body 定位 → extractTransfer()
```

---

## 二、门禁设计

### 为什么门禁用文本而非 ¥ 符号

余额页、账单列表页、红包页同样包含 ¥ 符号。仅用 ¥ 做门禁会导致非支付页被误触发。

`texts.first().startsWith("支付成功")` + `"完成" ∈ texts` 这两个条件同时满足的页面，在支付宝中只有**支付结果页**。

### texts 数量下限

`texts.size >= 4` 基于所有已知格式的最小值：锚点 + 类型文本 + 裸金额 + 至少一个 Body 项。

---

## 三、两种金额格式

### Format A: 嵌入格式（常规扫码支付）

根节点树的父 FrameLayout 的 `contentDescription` 包含完整的"支付成功￥xx.xx"：

```
FrameLayout desc="支付成功￥1.01"
  ├── ImageView (✓图标)
  ├── TextView "支付成功"
  └── FrameLayout
        ├── ImageView (¥图标)
        └── TextView "1.01"
```

texts 列表：
```
[0] 支付成功￥1.01    ← contentDescription，金额嵌入
[1] 支付成功          ← 类型文本
[2] 1.01             ← 裸金额
[3..]                ← Body 区键值对
```

**提取方式**：texts[0] 匹配 `^(支付成功|转账成功)[¥￥](\d+\.\d{2})$`，group(2) 即为实付金额。header 固定占 3 项：`[锚点, 类型文本, 裸金额]`。

### Format B: 拆分格式（碰一碰支付）

碰一碰页没有嵌入金额的 contentDescription。实付金额被拆为两个独立节点：

```
TextView "支付成功"
TextView "￥"          ← 裸货币符号，独立节点
TextView "8.83"        ← 裸数字，独立节点
```

texts 列表：
```
[0] 支付成功
[1] 回首页             ← 头部按钮
[2] ￥                 ← 裸 ¥
[3] 8.83              ← 实付金额
[4] 获得森林能量        ← 蚂蚁森林推广 (contentDescription)
[5] 好想来零食乐园       ← 商户
[6] ￥8.90            ← 原价
[7] 百次立减            ← 优惠标签
[8] -￥0.07           ← 优惠金额
[9] 付款方式
[10] 中信银行信用卡(1111)
[11] 完成
```

**提取方式**：texts[0] 不匹配 ANCHOR_REGEX → 进入 L2 fallback。在头部区域（前 HEADER_SCAN_LIMIT=5 项）内搜索裸 ¥/￥ 符号，其后紧跟纯两位小数 `^\d+\.\d{2}$` 即判定为实付金额。

---

## 四、Format A vs Format B 自动判别

两种格式的判别点只有一处：`ANCHOR_REGEX.find(texts[0])` 是否命中。

| | Format A (嵌入) | Format B (拆分) |
|------|------|------|
| texts[0] | `支付成功￥1.01` | `支付成功` |
| ANCHOR_REGEX 命中 | ✅ | ❌ |
| 金额提取路径 | L1（正则 group 2） | L2（头部扫描裸 ¥ + 裸数字） |
| header 结束 | texts[2]（裸金额） | texts[idx+1]（裸数字之后） |

两种格式互斥：嵌入格式的 texts[0] 包含中文和 ¥ 符号，永远不会被误判为裸 "￥"。拆分格式的 texts[0] 不含 ¥ 符号，永远不会被 ANCHOR_REGEX 命中。

---

## 五、支付成功页 — ¥ pair 自适应 Body 定位

### 问题：Body 起点不固定

Format A 的 header 固定 3 项，Body 从 texts[3] 开始。

Format B 的 header 构成不固定——碰一碰头部的"回首页"按钮和"获得森林能量"推广都是可变的。无法用固定 drop(N)。

### 方案：¥ pair 扫描

支付页 Body 中每一项都是 (Label, Value) 配对，第一个 ¥ 值通常是原价（商户名后的 "￥8.90"）。扫描条件：

```
从 paidEndIdx + 1 开始，找到第一个 i 满足:
  texts[i]   ∉ BUTTONS（不是按钮）
  texts[i+1] 匹配 ^[¥￥]\d+\.\d{2}$（是组合 ¥ 格式）
```

这个 `i` 就是 Body 起点。

### 推演

**Format A** — texts[2]="1.01" (paidEndIdx=2)，从 i=3 扫描：
```
i=3: "喜乐街奶茶店" + "￥1.01" → 按钮检查 ✓, ¥格式 ✓ → bodyStart=3
```

**Format B** — texts[3]="8.83" (paidEndIdx=3)，从 i=4 扫描：
```
i=4: "获得森林能量" + "好想来零食乐园" → "好想来零食乐园" 不匹配 ¥ 格式 → 跳过
i=5: "好想来零食乐园" + "￥8.90" → 按钮检查 ✓, ¥格式 ✓ → bodyStart=5
```

"获得森林能量"被自然跳过——它后面的"好想来零食乐园"不含 ¥，不满足 ¥ pair 条件。

### 为什么 YUAN_VALUE_REGEX 不会被头部裸 ¥ 误触发

`^[¥￥]\d+\.\d{2}$` 要求 ¥ 符号和数字在**同一个文本**中。Format B 头部的 "￥" 是独立的单字符节点，匹配不到此正则。

Body 区的 ¥ 值永远是组合格式节点，与头部裸 ¥ 形态互斥。

### L2 金额搜索为什么限域在 HEADER_SCAN_LIMIT

Body 区同样有 ¥ 值（原价 "￥8.90"），但它们都是组合格式，永远不会匹配 L2 的"裸 ¥ + 裸数字"条件。限域是额外保险。

---

## 六、转账成功页 — 纯文本 Body 定位

### 与支付页的差异

转账页 Body 不含 ¥ 值（收款方、交易方式均为纯文本标签对）。¥ pair 扫描不适用。

### 当前逻辑

Body 直接从 `paidEndIdx + 1` 开始，仅移除尾部按钮后 chunk 配对。

### 已知局限

拆分格式的转账碰一碰页**目前无实测数据**。如果未来此类页面头部也包含额外元素（按钮/推广），Body 起点定位可能需要调整为类似 parsePayment 的自适应扫描——但匹配条件不是 ¥ pair，而是纯文本键值对的结构特征。

## 七、付款提取（extractPayment）

从 pairs Map 中提取：

| 字段 | 提取方式 | 示例 |
|------|---------|------|
| 商户 | 第一个 value 以 ¥ 开头**且非负**的 key | `{"好想来零食乐园": "￥8.90"}` → "好想来零食乐园" |
| 原价 | 商户 key 对应的 ¥ 金额 | `parseAmount(pairs["好想来零食乐园"])` → 8.90 |
| 优惠 | value 以 `-¥` 或 `-￥` 开头的 entries | `{"百次立减": "-￥0.07"}` → `[("百次立减", -0.07)]` |
| 付款方式 | `pairs["付款方式"] ?: pairs["交易方式"]` | "中信银行信用卡(1111)" |

优惠校验日志：`原价 + 折扣总和 = 计算值`，与实付金额对比验证。仅做日志，不阻断解析。

---

## 八、转账提取（extractTransfer）

| 字段 | 提取方式 | 示例 |
|------|---------|------|
| 商户 | `pairs["收款方"]` | "鄂不韡韡" |
| 付款方式 | `pairs["交易方式"]` | "余额宝" |

转账无原价/优惠字段，自动分类为"转账"。
